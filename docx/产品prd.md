## 1. 项目背景与痛点分析

### 1.1 背景
当前B端中后台产品的原型设计与开发存在效率瓶颈。传统模式下，从需求到高保真原型再到代码实现，链路长且重复劳动多。AI技术的出现虽然带来了自动生成的可能，但目前的解决方案存在显著痛点。

### 1.2 核心痛点
1.  **AI 黑箱与不可控性**：AI直接生成的UI/UX往往缺乏一致性（"开盲盒"），难以符合严格的企业级B端规范，极度依赖大模型的随机能力。
2.  **维护困难**：AI通常直接生成HTML/CSS代码，用户难以进行可视化的二次编辑，一旦需要微调（如改个按钮颜色、换个列序），零代码基础人群难以实现，ai也难以实现某个组件的精确微调。
3.  **复用性差**：一次/多次生成的页面往往是孤立的，缺乏统一的组件库和设计系统支撑，如没有足够精确的ai Prompt往往也会导致整个系统风格割裂。

## 2. 产品愿景与解决方案

### 2.1 核心理念：配置驱动 + AI 辅助
**AIGen-UI** 旨在打造一个"中台化"的B端产品生成引擎。
- **抽象组件**：将输入框、下拉框、统计卡片、表格等常用B端组件抽象为标准化的、可配置的中台组件。
- **AI 赋能**：AI 模块**不直接画图**，而是作为"配置生成器"。它理解用户需求，生成符合系统架构规范的 JSON 配置文件，从而达到快速生成产品交互原型的目的。
- **配置驱动渲染**：前端引擎读取 JSON 配置，实时渲染出标准的、精美的、可交互的界面。

### 2.2 价值主张
- **标准化**：确保生成的每一个页面都符合 B 端设计规范。
- **可复用**：所有页面共用一套或多套组件库，风格统一，代码精简。
- **可视化定制**：用户不仅可以通过 AI生成，还能通过 UI 界面（Edit Mode编辑模式）直接修改配置，所见即所得。

## 3. 已实现功能架构

基于当前系统架构，已实现以下核心模块：

### 3.1 动态页面引擎
- **页面布局**：支持 Header, Sidebar (ShadcnLayout), Breadcrumb, Filter, Action, Card, Table 四大核心区域的布局。
- **配置协议**：定义了 `page-config.ts` 规范，支持组件的嵌套与属性定义。

### 3.2 可视化配置系统
用户无需接触代码，即可在界面上直接修改页面：
- **筛选区**：支持 Input, Select, DateRange, TreeSelect 等组件的增删改查与排序。
- **功能区**：支持按钮（Primary/Outline/Text/Shadcn）的配置，及交互效果（Modal, Drawer, Table Link）的绑定。
- **卡片区**：支持 KPI 统计卡片的动态配置。
- **表格区**：支持列宽、对齐、固定列、各种 Badge 状态样式及 Mock 数据规则的配置。

### 3.3 AI 配置助手
- **自然语言交互**：用户描述需求（如"生成一个用户管理表"），AI 自动输出 JSON。
- **配置追加与合并**：支持 AI 生成的配置与现有页面配置的智能合并。
- **实时预览**：生成即渲染，所见即所得。

### 3.4 模拟数据引擎
- **规则驱动**：前端根据列配置（如 `datetime`, `money`, `status`）自动生成逼真的 Mock 数据，解耦后端依赖。

### 3.5 产品原型与详细描述

#### 3.5.1 全局布局交互
- **侧边导航栏**：
    - **多团队切换**：顶部集成团队切换下拉菜单，支持用户在不同工作空间（Team）间无缝切换，不同团队拥有独立的导航菜单配置数据。
    - **动态导航**：支持多级树形菜单，提供折叠/展开交互。在**编辑模式**下，支持可视化的拖拽排序及快捷增删菜单项，操作即时生效。
- **顶部栏**：
    - **智能面包屑**：根据路由自动生成路径导航，支持点击层级快速跳转。
    - **快捷自定义区**：支持通过配置添加顶部快捷按钮或下拉菜单（如“系统设置”、“帮助文档”），同样支持拖拽布局。
    - **用户入口**：集成用户头像，点击唤起下拉菜单，作为进入“用户中心”、切换“编辑/预览模式”及“退出登录”的统一入口。

#### 3.5.2 动态工作台 (Dynamic Workspace) - Page1
页面主体采用积木式设计，由四大核心配置区域组合而成：
1.  **筛选查询区**：
    - 支持 `Input` (模糊搜索), `Select` (下拉筛选), `DateRange` (时间范围), `TreeSelect` (树形组织选择) 等多种表单组件。
    - 采用响应式 Grid 布局，自动适应不同屏幕分辨率。
2.  **操作功能区**：
    - 位于筛选区下方或右侧，承载全局操作（如“新增用户”、“批量导出”）。
    - **交互绑定**：按钮可配置点击反馈，包括“无动作”、“打开弹窗表单 (Modal Form)”或“打开关联表格弹窗 (Modal Table)”。
3.  **数据卡片区 (Card Area)**：
    - 用于展示核心业务指标 (KPI)，支持配置标题与动态数值（如“本月销售额: ¥1,200”）。
    - 视觉上采用卡片式设计，突出关键信息。
4.  **数据表格区**：
    - **高度可配**：支持自定义列宽、对齐方式、固定列（Fixed Left/Right）。
    - **富文本列**：支持普通文本、徽标 (Badge)、状态点 (Status Dot) 及操作按钮组 (Action Buttons) 等多种显示形态。
    - **智能模拟**：内置 Mock 引擎，可根据列定义的类型（如时间、金额、状态）自动生成符合逻辑的测试数据。

#### 3.5.3 AI 智能助手
- **悬浮球入口**：页面右下角常驻 AI 悬浮按钮，支持全屏拖拽停靠，确保不遮挡业务内容。
- **沉浸式对话**：
    - **意图理解**：通过自然语言（如“帮我把第一列改成ID，并加上搜索功能”）识别用户对页面配置的修改意图。
    - **实时生成与预览**：AI 生成 JSON 配置后，系统页面会直接应用到“预览模式”，直观展示新增/修改的组件详情。
    - **一键应用**：用户确认预览无误后，点击“确认追加”，配置即刻合并并渲染到当前页面，实现“所想即所得”。

#### 3.5.4 个人中心
- **基本资料管理**：提供头像上传（支持图片预览与裁剪）、昵称修改等基础功能。
- **团队与权限**：
    - **团队管理**：支持创建新团队、查看已加入的团队列表。
    - **角色视图**：展示当前用户在各团队中的角色（如 Owner, Admin, Viewer），未来版本将据此控制菜单与按钮的可见性。

## 4. 产品迭代规划 (Roadmap)

### 4.1 阶段一：基础功能完善与体验优化 (当前阶段)
- [x] 完善 V9 配置架构。
- [x] 实现 Edit Mode 全流程可视化编辑。
- [x] 集成 Coze/AI API 实现配置生成。
- [ ] ai修改当前页面配置。

### 4.2 阶段二：丰富组件库与模板
- **目标**：增加更多可抽象的中台化组件，覆盖更多业务场景。
- **新增组件**：
    - **高级图表**：引入 ECharts/AntV，通过配置生成折线图、饼图、柱状图。
    - **复杂表单**：支持分步表单 (Step Form)、分组表单。
    - **详情页**：支持描述列表 (Description List)、时间轴 (Timeline)。
- **模板市场**：内置 CRM、ERP、CMS 等行业的标准模板页面。

### 4.3 阶段三：真实数据接入
- **目标**：从"B端原型工具"进化为"低代码开发平台"。
- **API 编排**：支持在配置中绑定真实的 API URL。
- **AI SQL 生成**：AI 不仅生成前端配置，还协助生成后端 SQL 建表语句和查询逻辑。
- **数据绑定**：实现前端组件与真实后端数据的双向绑定。

### 4.4 阶段四：企业级权限控制 (RBAC & Security)
- **目标**：实现精细化的权限管理，保障数据安全。
- **角色管理**：引入 RBAC 模型，定义 Admin, Editor, Viewer 等角色。
- **颗粒度控制**：
    - **页面级**：谁能访问某个页面。
    - **组件级**：谁能看到某个按钮（如"删除"按钮仅管理员可见）。
    - **字段级**：敏感数据（如手机号）脱敏显示。
